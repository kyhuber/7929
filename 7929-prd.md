# 7929 — Home Maintenance PWA

**Product requirements document**
Version 1.0 · July 2026
Property: 7929 17th Ave SW, Seattle, WA 98106

---

## 1. Summary

A single-user progressive web app for tracking recurring home maintenance and a running backlog of one-off projects. Modeled on the interval-based logic of plant-care apps (Planta) rather than fixed-date calendaring: every task has a cadence, a last-completed date, and a computed due-ness. Nothing is ever "missed" — only overdue by *N* days.

The app replaces an abandoned attempt at Google Tasks and calendar reminders, which failed because they were general-purpose tools opened with competing intent. This app is dedicated, lives on the iPhone home screen, and answers one question on open: **what needs doing right now?**

---

## 2. Goals

| Goal | Success looks like |
|---|---|
| Eliminate the nightly "should I do something?" negotiation | Open app → top of screen says what to do → do it |
| Make small projects visible instead of mental | The caulk job sits in a list, not in my head |
| Absorb slippage without collapse | Doing a task 4 days late recalibrates silently |
| Handle seasonal change automatically | Mowing cadence tightens in June without me thinking about it |
| Survive years of history | Completion records are durable and backed up |

## 3. Non-goals

- Multi-user, sharing, or accounts beyond a single owner
- Desktop-first design (desktop should be usable, not optimized)
- Native app distribution
- Inventory of every consumable or receipt (v3 at earliest)
- Gamification, streaks, or scoring — slippage must not carry penalty framing

## 6. Core logic

### Effective interval

```
effectiveInterval(task, date):
  month = date.getMonth() + 1
  for override in task.seasonal_overrides:
    if month in override.months: return override.interval_days
  return task.base_interval_days
```

### Due-ness

```
dueDate     = last_completed_at + effectiveInterval(task, today)
daysOverdue = floor((today - dueDate) / 1 day)
```

| `daysOverdue` | Status | Treatment |
|---|---|---|
| ≥ 1 | Overdue | Top of list, warm accent |
| 0 | Due today | Top of list, neutral emphasis |
| −1 to −3 | Coming up | Secondary section |
| ≤ −4 | Scheduled | Hidden from Today |

Sort Today by `daysOverdue` descending. A task with no `last_completed_at` is treated as due today.

### Seeding rule

**Do not backdate every task to zero.** On first run, stagger `last_completed_at` so the app opens with 3–5 items due, not forty. Nothing kills a system faster than a wall of red on day one. Seed values are specified in §9.

### Catch-up rule

Completing a task always sets `last_completed_at = now()`. Intervals slide forward from actual completion, never from the theoretical due date. No accumulation, no debt, no streak to break.

## 7. Screens

### 7.1 Today (home)

The default view and the reason the app exists.

- **Overdue** section, sorted most-overdue first
- **Due today** section
- **Coming up** section (next 3 days), collapsed by default
- Each row: task name, category icon, est. minutes, days-overdue chip
- Tap row → completes it, with undo toast (5 sec)
- Tap name → task detail
- If nothing is due: a plain empty state naming the next thing coming, plus a prompt toward the project backlog. No congratulation, no confetti.

**Time filter chips:** `Any` · `≤15 min` · `≤30 min`. Filters both recurring and projects by `est_minutes`. This is the mechanism that converts a free half-hour into completed work.

### 7.2 Projects

The running backlog. Ordered by priority, then by age.

- Grouped: `Next` · `Soon` · `Someday`
- Each row: name, location, est. minutes, materials indicator if `materials` is set
- Complete → sets `status = done`, writes a completion row, drops off the list
- Quick-add: name + est. minutes only, everything else optional and editable later. Friction here is the enemy; the whole point is capturing the caulk job in ten seconds when it occurs to me.

### 7.3 All tasks

Browse recurring tasks by category. Each row shows cadence and next due date. This is the maintenance-and-tuning surface, not a daily view.

### 7.4 Task detail

- Name, category, steps list (reference only)
- Cadence editor: base interval, plus seasonal overrides
- `Last completed`, `Next due`
- Completion history, most recent 10
- Actions: complete · snooze 3/7/14 days · edit · archive

### 7.5 Add / edit task

Single form serving both kinds. Kind toggle at top; interval fields hide for projects.

## 8. Design direction

Draw the palette from the house itself rather than a generic app theme. The paint colors are known:

| Token | Source | Approx. hex |
|---|---|---|
| Background | SW 6119 Antique White | `#EAE0CF` |
| Surface | SW 7036 Accessible Beige | `#D3C7B5` |
| Text primary | Deep warm brown | `#2E2721` |
| Accent | Sage green (kitchen cabinetry) | `#8A9A7B` |
| Overdue accent | Douglas fir / warm amber | `#B5793A` |

Hexes are approximations — tune against the real thing. Deliberately **not** red for overdue; the tone should read as "this is waiting for you," not "you have failed." Warm amber does that work.

Typography: one humanist sans throughout, generous line height, large touch targets. No decoration. The app should feel like it belongs in the same house as the danish-oiled glulam beam.

## 10. Phasing

### v1 — the working app

Everything in §5–§9. Local session, Supabase persistence, installed to home screen. No notifications. Success criterion: it gets opened without a reminder, because it's on the home screen and answers a real question.

### v2 — the nudge

- **App icon badge count** for overdue items. Highest value per unit of effort — a red `3` on the icon does most of what a notification does, without interruption.
- **Web push** via Vercel cron → `web-push` with VAPID keys → subscription stored in Supabase. Constraints: iOS 16.4+, requires home-screen install, permission must be requested from a tap, no local scheduled notification API exists. A single daily morning push is the right cadence; more is noise.

### v3 — the house record

Ties into the broader goal of a single home reference:

- Appliance registry: make, model, serial, purchase date, warranty expiry, manual PDF link
- Photo attachments on completions ("grout before/after")
- Cost tracking per project
- Contractor contact list

## 11. Open questions for build time

1. Should `Rain garden water` use an `active_months` field rather than archive/unarchive? Cleaner, slightly more schema.
2. Does the time-filter chip belong on Projects as well as Today? Probably yes.
3. Offline behavior for v1 — read-only cache, or queue writes? Simplest acceptable answer is a service worker cache of the last-loaded state, with writes requiring connectivity.
